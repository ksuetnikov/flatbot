# Текущее состояние

Зафиксировано по коду, миграциям, тестам и конфигурации. Приложение в этой сессии целиком в браузере не проходилось. Go-бот не запускался и в репозитории отсутствует.

## Реализовано и подтверждается кодом

- Регистрация и сессия веб-пользователя, профиль, смена пароля, сброс пароля, переключение темы. Каркас starter kit, на него есть feature-тесты.
- CRUD объектов владельца с дашборда и карточки: создание с именем по умолчанию, правка имени, описания и расписания, удаление.
- Карточка объекта со сводкой финансов, списком счётчиков и статусом сдачи показаний за текущий месяц.
- Подписчики: создание со слотом Telegram и случайным ключом из 8 символов, смена имени и ключа, запрет смены ключа после появления `telegram_id`, перегенерация ключа, удаление подписчика вместе со слотом, дозаполнение слотов при открытии настроек.
- Счётчики: создание, правка имени и кода, удаление, история показаний, правка и удаление показания, синхронизация `object_properties.value`.
- Файлы счётчика из панели и одно фото на показание из API. Удаление файла с диска в событии модели.
- Финансы: добавление, удаление, помесячная группировка, итоги.
- Экспорт показаний и финансов в XLSX с итогами доходов и расходов за период.
- Приём `POST /api/meters/` и `POST /api/meters/{readingId}/photo`.
- Команда полного сброса `app:reset`.
- Каст и UI ежемесячного напоминания: день и время, без выбора месяца как бизнес-поля.

## Реализовано частично

- Интеграция с Go. Общая схема таблиц и комментарии есть. Исходящий HTTP написан, но событие `AfterUpdateObjectEvent` не диспатчится, а конфигурация просит не задавать URL при общей базе. Входящие поля бота (`telegram_id`, `state` после регистрации, `user_code`, `bot_properties`, журнал напоминаний) PHP не записывает.
- Авторизация домена. Middleware пускает только вошедшего пользователя. Проверки «объект мой» и политики нет. Часть вложенных операций проверяет объект, часть нет.
- Верификация email. Маршруты и страницы есть, модель пользователя контракт не реализует, middleware `verified` пользователя не останавливает.
- Роль администратора бота. Колонка и сидер есть, панель флаг не использует.
- Сортировка. Колонка `order` обязательна и всегда пишется как `1`.
- Мягкое удаление. Колонки `deleted_at` есть, трейт не подключён, удаление физическое.
- `description` у счётчика и подписчика в схеме есть, формы его не редактируют.
- Очередь поднята в `composer run dev`, прикладных задач, которые реально ставятся при работе панели, нет.

## Выглядит незавершённым

- `ObjectCreateResource` не используется.
- `ObjectModelPolicy` ссылается на класс `App\Models\ObjectModel`, которого нет. Все методы возвращают `false`.
- Закомментированные `$this->authorize(...)` в `ObjectController` и `SubscribeUserController`.
- `ObjectPropertyService::delete` называет параметр `$subscribeUserId` и удаляет свойство по id без объекта.
- `DatabaseSeeder` создаёт объекты на `user_id = 1` и не создаёт этого пользователя.
- `routes/console.php` — демонстрационная команда `inspire`.
- В `composer.json` скрипт `cs-fix` ссылается на неподключённый `php-cs-fixer`.
- README репозитория содержит команды генерации SSH-ключа и одну строку про `composer run dev`. Описания продукта там нет.
- Поиск `TODO` и `FIXME` по `app`, `resources/js`, `database`, `routes` совпадений не дал. Единственная пометка устаревания в прикладном коде — комментарий `config/services.php` про Go API и `@deprecated` у `toDatetimeLocalValue` в `resources/js/lib/notification-schedule.ts`.

## Технический долг и риски

- Любой вошедший пользователь может открыть и изменить чужой объект, зная id. Для удаления счётчика и подписчика достаточно числового id, объект из URL не сверяется.
- `POST /api/meters/` и загрузка фото доступны без аутентификации любому, кто достучится до приложения. Можно записать показание на любой существующий счётчик и прикрепить фото к любому показанию.
- Удаление объекта оставляет строки `telegram_users`. Удаление подписчика через сервис эти строки удаляет. Два пути расходятся.
- Уникальность регистрационного ключа не защищена индексом.
- `reading_reminder_logs` очищается целиком при любой смене `notification_date`, включая правку времени. Повторная отправка напоминаний после этого зависит от бота. Поведение бота не проверено.
- Исходящая задача при ошибке Go считается успешной и не повторяется.
- `TelegramUserSeeder` хранит фиксированный ключ администратора бота в репозитории.
- SQLite-ветка миграции `telegram_users` пересобирает таблицу сырым SQL. Откат и прогон на MySQL отличаются. Общая база с ботом на не-SQLite не проверялась.
- Миграция журнала напоминаний от 2026-06-15 удаляет все уже накопленные строки.
- Фабрика объекта пишет `notification_date` через `toISOString()`, то есть UTC-строку, тогда как рабочий каст ожидает настенное время.
- Экспорт и статус месяца используют часовой пояс приложения и `now()`. Совпадение границы месяца с тем, как бот считает период, не проверено.
- На PHP 8.5 стоковый конфиг Laravel 12.20.0 пишет deprecation `PDO::MYSQL_ATTR_SSL_CA` при каждой загрузке конфигурации, даже если соединение SQLite. Обход есть в `config/database.php`. Vendor-копия фреймворка в git не фиксируется.

## Что проверить вручную

- Регистрация, создание объекта, счётчик, подписчик, копирование ключа, появление `telegram_id` после регистрации в живом боте.
- Приём показания и фото тем клиентом, которым пользуется бот, и отображение их на карточке и в истории.
- Смена расписания и то, перестаёт ли бот считать напоминание уже отправленным.
- Экспорт XLSX на реальных данных: даты, итоги, пустой период.
- Загрузка файла больше нескольких мегабайт через `composer run dev` и через другой способ запуска PHP, где лимиты 12M не выставлены.
- `app:reset` только на копии базы.
- Открытие объекта другим пользователем панели. Ожидаемое продуктовое поведение в коде не защищено.

## Нельзя подтвердить без запуска или другого репозитория

- Что Go-бот действительно читает эти таблицы и вызывает `/api/meters`.
- Формат, в котором бот пишет `bot_properties`, `user_code`, `state` и журнал напоминаний.
- Совпадает ли ключ сидера с текущим `init.sql` бота.
- Часовой пояс и путь к файлу SQLite в процессе бота.
- Работоспособность почтовых драйверов, AWS, Redis, Memcached: в доменном коде они не используются, в примере почта пишется в лог.
- Пакет тестов на текущей машине: в сессии документации `php artisan test` не запускался.
